# 科研架构 (Research Architecture)

## 定位

这是一个**诊断+指导工具**。它基于从8份权威材料中蒸馏并验证的"三层四步，双回环，六参数"架构，帮助社科人文研究者：

- 定位当前研究阶段
- 识别各阶段的关键任务和常见问题
- 获得可追溯来源的方法论指导

**它不是**：写作模板、通用规范清单、"正确方法"的断言。

所有建议都标注来源——你可以追溯到是哪个学者、哪篇材料支撑了这个判断。

## 触发方式

- "我在选题阶段，卡住了" → 先由本技能定位研究阶段，再引导至 `topic-problematization` 做深度选题诊断
- "帮我看看我的论证结构"
- "我的方法论设计有问题吗"
- "论文改不下去了，怎么办"
- "我的研究到哪一步了？"

## 与其他子技能的关系

`research-architecture` 是**横向广度框架**——它覆盖选题→执行→收敛的完整研究生命周期，帮助研究者定位"我现在在哪一步"。

`topic-problematization` 是**纵向深度框架**——它专精于架构中的第一步（锚定/选题），提供选题阶段的完整诊断流程。

`research-execution` 是**纵向深度框架**——它专精于架构中的第二步（执行/设计），覆盖理论推导→方法辩护完整链。

`research-contribution` 是**纵向深度框架**——它专精于架构中的第三步（收敛/贡献），诊断贡献类型、建构质量、表述有效性和局限真诚性。

**同时触发不是冲突，是分工**：当用户说"卡在选题"，architecture 先做横向定位（"你在锚定层"），然后引导至 topic-problematization 做纵向深入（"你的选题驱动类型是什么？"）。同理，"不知道贡献够不够"→ architecture 定位收敛层 → research-contribution 深入诊断。

## 核心架构：三层四步，双回环，六参数

```
第一层：锚定（ANCHOR）
  Step 1: Topic → Question → Hypothesis Tree / Thesis
  文献对话贯穿全程
  权重最高（王汎森："选题=70%成功"）
       ↕ 【内回环】写作中的发现 → 修正假设
第二层：执行（EXECUTE）
  Step 2: 研究设计 + 方法辩护
  Step 3: 分析 + 论证构建
  写作深度介入——不是记录，是研究的继续
       ↕ 【外回环】闭环检查 → 暴露不足 → 修正
第三层：收敛（CONVERGE）
  Step 4: 贡献定位 + 闭环检查 + 迭代修正
```

## 诊断模式

### 当用户说"卡住了"

1. 先定位用户在哪一层、哪一步
2. 基于该步骤的诊断清单提问
3. 给出可追溯来源的建议

### 第一层诊断：锚定

> **深入选题诊断** → 调用 `topic-problematization`。以下问题用于快速定位，深度诊断（驱动类型分析、六要素检验、选题辩护建构）由 topic-problematization 提供。

| 诊断问题 | 如果答不上来 | 来源 |
|----------|-------------|------|
| 你能用一句话说出你的研究问题吗？ | 还在 topic 阶段，需要缩小 | 陆铭："走完topic到question的距离才迈出第一步" |
| 这个问题为什么值得研究（理论上+实践上）？ | 需要做选题辩护 | 陆铭：重要性论证 |
| 你的核心假设是什么？能分解为子假设吗？ | 缺少假设树 | 李怀祖：假设树是智力钥匙 |
| 最相关的文献有5-10篇吗？ | 文献对话不足或过度 | 陆铭：文献三分法 |
| 子假设能对应到可观测的证据吗？ | 假设太抽象 | 李怀祖：落实到变量层次 |

### 第二层诊断：执行

> **深入执行/设计诊断** → 调用 `research-execution`。以下问题用于快速定位，深度诊断（理论推导A1-A4、文献对话贯穿、方法辩护C1-C3）由 research-execution 提供。

| 诊断问题 | 如果答不上来 | 来源 |
|----------|-------------|------|
| 为什么用这个方法而不是别的？ | 方法辩护缺失 | 陆铭："起点由理解决定，不是数学" |
| 方法设计能回答你的研究问题吗？ | 方法-问题脱节 | 李怀祖：控制+测量 |
| 你的分析方法能排除替代解释吗？ | 论证不够严谨 | 柳武妹2025：替代解释排除 |
| 你写了几遍？发现最初的问题变了吗？ | 可能在抗拒内回环 | 陆铭："改20遍才知道要写什么" |

### 第三层诊断：收敛

> **深入贡献诊断** → 调用 `research-contribution`。以下问题用于快速定位，深度诊断（贡献类型定位、六路径建构诊断、Discussion表述、局限真诚性）由 research-contribution 提供。

| 诊断问题 | 如果答不上来 | 来源 |
|----------|-------------|------|
| 你的贡献是什么（不是"做了什么"是"增加了什么"）？ | 贡献表述不清 | 陆铭+李怀祖 |
| 读者能进得来、留得下、记得住吗？ | 需闭环检查 | 三层结构：功能三模块 |
| 哪些局限是你真诚反思的 vs. 例行公事的？ | 收敛不实 | 陆铭："结论要准确，不能夸大" |

## 六参数：架构的适用范围

不同方法论路径下，架构的表现形式不同。诊断时需先确认用户的研究类型：

| 参数 | 如果你做定量研究 | 如果你做定性研究 | 来源 |
|------|----------------|----------------|------|
| 假设来源 | 理论演绎为主 | 现象归纳或理论借用 | 海淼2026 vs. 柳武妹2025 |
| 假设形态 | 变量关系式 | 过程模型/概念框架 | 李怀祖 vs. 案例研究实践 |
| 论文结构 | IMRaD规范 | 自由结构 | 三层结构分类 |
| 方法辩护 | 替代解释排除 | 方法论传统+三角验证 | 柳武妹2025 vs. 海淼2026 |
| 锚定时点 | 前置 | 渐进（内回环幅度大） | 实证论文对比 |

## 关键提醒

1. **架构是地图，不是铁轨**：你可以偏离它，但应该知道自己在偏离什么
2. **内回环是正常的，不是失败的标志**：改到第20遍才清楚自己要说什么是研究常态，不是能力不足
3. **线性叙事 ≠ 线性研究**：发表论文的整洁结构是对混乱研究过程的后期重构，不要被它误导
4. **收敛层最容易被空洞化**：真正区分论文质量的在锚定和执行层，不在结论的修辞（综合推断自：陆铭"结论要准确，不能夸大"+ 三层结构"闭环检查才能发现研究不足"+ 王汎森"选题=70%成功"——结论的质量取决于前三步是否真正深入，而非结论段落的文字修饰）
